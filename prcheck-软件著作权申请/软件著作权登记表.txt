四、软件主要功能与技术特点（创新点）
--------------------------------------------------------
1. PR 差异安全检查：对 git diff 逐行分析新增代码，内置 21 条规则，覆盖
   安全（硬编码密钥、命令注入、SQL 注入风险、Session Cookie 安全配置、
   不安全反序列化、弱密码学、危险函数等）、数据（敏感个人信息、数据库
   直连等）、行为（错误处理、超时、依赖锁定等）三类检查项，每项均给出
   文件:行号 定位与修复建议（hint）。
2. OpenAPI 语义化变更清单：对 swagger 2.0 / OpenAPI 3.x 两份规范做语义
   差异分析，识别端点、参数、schema 的新增/删除/修改，并按破坏性变化
   自动建议 semver 版本号（breaking → major / feature → minor / fix → patch）。
3. 多种报告输出：Markdown（可直接作为 PR 评论）、SARIF 2.1.0（可接入
   GitHub Code Scanning）、JSON、命令行文本，支持 --min-severity 与
   security/data/behavior 分类过滤。
4. 合并门禁：--require-high-ok 模式下，存在未解决 High 级问题时以非零
   退出码失败构建，阻断高风险合并。
5. GitHub 集成：可作为 composite GitHub Action 运行，自动从
   git diff base...head 派生分析对象；可选把报告以 PR 评论形式发布
   （幂等更新，不重复堆叠）、把 high/medium 发现内联到变更行评审评论、
   读取 PR 实时可合并状态、以及当门禁失败/通过时同步添加/移除
   prcheck:blocked 标签。
6. 轻量零训练：分析引擎为纯本地规则引擎（正则/令牌分析 + 确定性 OpenAPI
   语义 diff），无训练数据、默认路径无网络依赖、无 LLM，仅依赖标准库与
   PyYAML，适合在 CI 中快速执行。
7. 增量缓存：基于内容哈希的增量分析缓存，未变化文件的结论可复用，加速
   重复分析。
8. 测试完备：fixture 驱动的单元测试覆盖规则引擎、OpenAPI 差异、渲染、
   CLI 退出码策略、GitHub 接口调用（含失败降级），无需真实网络。
