1 引言
================================================================

1.1 编写目的
------------
本手册面向 prcheck 的使用者（开发人员、代码评审人员、CI 维护人员），
说明软件的安装、配置、操作方法与常见故障处理。读者无需具备工具源码
知识，只需了解基本命令行操作与 Git 概念。

1.2 软件概述
------------
prcheck 是一款对 GitHub Pull Request 差异（diff）进行自动化安全合规
检查的命令行/CI 工具，同时支持对 OpenAPI 规范变更输出语义化版本
（semver）建议。输出内容包括：
- 按 Security / Data / Behavior 分类的检查清单（含 文件:行号 定位）；
- OpenAPI 变更清单与版本提升建议；
- Markdown（PR 评论）、SARIF 2.1.0（代码扫描）与 JSON 报告。

1.3 运行环境
------------
- 操作系统：Linux / macOS / Windows；
- 解释器：Python 3.10 及以上；
- 可选依赖：PyYAML（仅 OpenAPI 解析需要，可自动安装）；
- 可选工具：gh CLI（仅使用 --repo/--pr 拉取 PR 时可用，需已登录）；
- CI：GitHub Actions（以 composite Action 方式调用）。

2 安装与卸载
================================================================

2.1 安装
--------
方式一（推荐，源码/本地安装）：
    python3 -m venv .venv
    .venv/bin/pip install -e .
    .venv/bin/prcheck --version
方式二（GitHub Action）：在 workflow 中通过 uses: 引用本仓库的 action 目录。

2.2 卸载
--------
    .venv/bin/pip uninstall prcheck
如需彻底清除缓存，可删除分析缓存目录 .prcheck-cache/。

3 操作说明（按功能模块）
================================================================

3.1 模块一：PR 差异检查（安全/数据/行为清单）
--------------------------------------------
准备 diff 文件：
    git diff origin/main...HEAD > /tmp/pr.diff
执行分析并输出到终端：
    prcheck -d /tmp/pr.diff
写 Markdown 报告到文件：
    prcheck -d /tmp/pr.diff -o report.md
导出 SARIF 日志：
    prcheck -d /tmp/pr.diff --sarif report.sarif
输出结构化 JSON：
    prcheck -d /tmp/pr.diff --json
直接拉取 GitHub PR 分析（需要 gh CLI）：
    prcheck --repo owner/repo --pr 123
查看输出：
- 每条发现均含 规则编号、类别、严重级别、文件:行号、问题说明与修复提示；
- 报告按类别与严重程度组织，High 级未解决问题会高亮显示门禁状态。

3.2 模块二：OpenAPI 变更清单与版本建议
--------------------------------------
    prcheck -d /tmp/pr.diff \
            --openapi-old spec_v1.yaml --openapi-new spec_v2.yaml
输出内容：
- 端点、参数、schema 的新增/删除/修改明细；
- 破坏性变化分类（breaking / non-breaking）；
- 建议的 semver 版本提升（major / minor / patch）及理由。

3.3 模块三：过滤与门禁
----------------------
分类过滤：
    prcheck -d /tmp/pr.diff --security-only     # 仅安全类
    prcheck -d /tmp/pr.diff --data-only         # 仅数据类
    prcheck -d /tmp/pr.diff --behavior-only     # 仅行为类
按最低严重级别过滤：
    prcheck -d /tmp/pr.diff --min-severity high
CI 门禁退出码策略：
    prcheck -d /tmp/pr.diff --exit-code fail-at-high
    prcheck -d /tmp/pr.diff --exit-code fail-at-medium
等价用法（兼容）：
    prcheck -d /tmp/pr.diff --require-high-ok
说明：门禁模式下，当存在达到阈值的未解决发现时，进程以非零退出码退出，
CI 构建即失败。

3.4 模块四：GitHub Action 集成
------------------------------
在 workflow 中配置：
    steps:
      - uses: owner/prcheck@v1
        with:
          diff: ""                 # 留空时自动 git diff origin/main...HEAD
          require-high-ok: "true"
          post-comment: "true"     # 发布报告为 PR 评论（幂等更新）
          post-inline-comment: "true"  # high/medium 发现内联到变更行
          check-mergeable: "true"  # 读取 PR 实时合并状态写入日志
          sync-labels: "true"      # 门禁失败加 prcheck:blocked 标签
结果产物写入 GITHUB_WORKSPACE 下 prcheck-reports/（可配置 output-dir）：
    report.md、report.sarif、semver.json。
说明：外部集成（评论/标签/合并状态）任一失败都不影响门禁判定，只记录
警告日志。

3.5 模块五：增量缓存
--------------------
默认启用分析缓存（目录 .prcheck-cache/），避免对未变化输入重复分析；
禁用方式：prcheck -d /tmp/pr.diff --no-cache。

4 配置与参数
================================================================

4.1 命令行参数一览
------------------
  diff / -d/--diff-file   差异文件路径（二选一）
  --repo、--pr            通过 gh CLI 拉取指定仓库/编号的 PR
  --openapi-old、--openapi-new  参与比对的旧/新 OpenAPI 规范文件
  -o/--output             写 Markdown 报告的文件路径（默认终端）
  --sarif                 写 SARIF 日志的路径
  --json                  以 JSON 输出结构化结果（优先于 -o）
  --security-only / --data-only / --behavior-only  分类过滤
  --min-severity          最低输出级别：info|low|medium|high（默认 info）
  --require-high-ok       存在 High 时退出码非零（门禁）
  --exit-code             退出策略：pass|fail-at-high|fail-at-medium
  --llm-summary / --mock-llm   启用默认关闭的模拟摘要器（不联网）
  --base-dir              相对路径解析基准目录
  --cache-dir             缓存目录（默认 .prcheck-cache）
  --no-cache              禁用缓存

4.2 GitHub Action 输入（在 action.yml 中声明）
----------------------------------------------
  diff、base-spec、head-spec、base-ref、head-ref、output-dir、
  require-high-ok、security-only、data-only、behavior-only、
  min-severity、post-comment、post-inline-comment、
  check-mergeable、sync-labels。

4.3 环境变量
------------
  GH_TOKEN / GITHUB_TOKEN  发布评论、读取合并状态、同步标签所需令牌
                           （需对应 write/read 权限）；
  GITHUB_API_URL           自定义 GitHub API 基址（企业版）。

5 故障处理与 FAQ
================================================================

5.1 常见问题
------------
Q1：提示 "python3 is required but not installed"？
    需先安装 Python 3.10+。
Q2：OpenAPI 文件解析报错 / 退出码为 2？
    请检查规范文件为合法的 YAML/JSON 且结构符合 swagger 2.0 或
    openapi 3.x；修复规范后重试。
Q3：--repo/--pr 拉取 PR 失败？
    确认已安装 gh CLI 且已登录（gh auth status），并具有目标仓库读取权限。
Q4：Action 中 post-comment 未生效？
    确认提供了 GITHUB_TOKEN 且授予 pull-requests: write 权限，并检测到
    PR 编号（pull_request 事件）。日志中会给出明确原因。
Q5：repeat 运行后评论重复堆叠？
    正常不会：报告评论与内联评论均带唯一标记，重跑时原地更新或跳过。
Q6：cache 相关日志说明？
    .prcheck-cache/ 仅缓存未变化输入的中间结论，删除缓存目录可随时重建。

5.2 退出码约定
--------------
  0  分析完成，门禁通过；
  1  门禁拦截（--require-high-ok/--exit-code 触发）；
  2  输入错误（如非法 OpenAPI 规范）。

5.3 技术支持与限制
------------------
- 规则引擎为纯本地实现，不连接网络、不含训练数据；违约场景以提示为准，
  不承诺穷尽所有可能性；
- 本手册未尽事宜请参阅设计说明书；
- 本软件由许达在中国移动研究院独立开发。如遇问题，请附带版本号与
  运行日志反馈。
