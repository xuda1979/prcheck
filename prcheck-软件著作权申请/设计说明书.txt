1 引言
================================================================

1.1 编写目的
------------
本说明书描述 prcheck（PR 安全清单与 OpenAPI 变更门禁分析工具）V1.0
的系统设计，供程序开发、测试、维护以及软件著作权登记审查使用。读者对象
为软件开发人员、测试人员、质量保障人员与著作权登记审查人员。

1.2 项目背景
------------
prcheck 面向 GitHub Pull Request 代码评审场景，解决"人工逐行审阅 PR
差异成本高、易遗漏安全项"的问题。工具对 PR 差异（diff）进行自动化规则
检查，并对 OpenAPI 规范变更给出语义化版本建议，输出可操作的检查清单，
作为 CI 合并门禁的一部分。

1.3 术语与缩略语
----------------
- PR：Pull Request，拉取请求。
- diff：文件差异，即新增/删除行的补丁文本。
- OpenAPI：OpenAPI 规范（含 swagger 2.0 与 openapi 3.x）。
- SARIF：Static Analysis Results Interchange Format，静态分析结果交换格式。
- semver：语义化版本号（major/minor/patch）。
- 门禁：构建或合并前的质量检查关卡。

1.4 参考资料
------------
- GB/T 8567-2006《计算机软件文档编制规范》
- OpenAPI Specification 3.x / Swagger 2.0 规范
- GitHub REST API 文档（issues / pulls comments、labels 接口）
- SARIF 2.1.0 规范

2 总体设计
================================================================

2.1 设计目标与约束
------------------
- 纯本地分析：规则引擎与 OpenAPI 差异引擎不依赖网络与训练数据，默认路径
  无 LLM，便于 CI 快速、确定性地执行。
- 最小依赖：仅依赖 Python 标准库与 PyYAML（仅 OpenAPI 解析需要）。
- 可嵌入：既可以作为本地命令行工具运行，也可以作为 GitHub composite
  Action 在 CI 中运行。
- 失败亲和：任何外部集成（评论、标签、合并状态读取）失败都仅降级为日志
  警告，不改变门禁判定结果。

2.2 系统结构（逻辑架构）
------------------------
系统由以下层次构成：

1) 接入层（CLI / GitHub Action 入口）
   - prcheck/cli.py：命令行解析、输入组织、输出渲染入口。
   - action/run_action.py：GitHub Action 执行入口，负责环境输入读取、
     报告产物写出、外部集成调用与退出码策略。
   - action/webhook.py：Webhook 桥接（报告评论的 upsert 通道）。
2) 分析层（核心引擎，纯本地）
   - prcheck/engine.py：run_analysis()，编排差异分析与 OpenAPI 差异分析，
     汇总问题清单（Issue）、统计信息与 semver 建议。
   - prcheck/rules.py：规则定义与匹配引擎，对 diff 的新增行逐行执行内置
     规则（安全/数据/行为三类）。
   - prcheck/diff.py：差异解析与行号定位，负责从 diff 中提取路径、新增行。
   - prcheck/openapi.py：OpenAPI/swagger 语义差异分析，输出端点/参数/
     schema 变更及破坏性分类。
3) 数据层
   - prcheck/issues.py：Issue 数据结构与排序/汇总工具。
   - prcheck/cache.py：基于内容哈希的增量分析缓存。
4) 渲染层
   - prcheck/render.py：Markdown / SARIF / JSON / 纯文本报告渲染。
5) 集成层（GitHub）
   - action/gh_comment.py：GitHub REST API 封装（评论 upsert、内联评审
     评论、PR 状态读取、阻塞标签同步）。
6) 可选扩展层
   - prcheck/llm.py：默认关闭的模拟摘要器，为未来真实 LLM 集成预留接口。

2.3 模块划分与职责
------------------
| 模块文件          | 职责 |
|-------------------|------|
| prcheck/cli.py    | 命令行入口、参数过滤、退出码 |
| prcheck/rules.py  | 21 条内置规则定义与逐行匹配 |
| prcheck/diff.py   | diff 文本解析、路径/行号提取 |
| prcheck/openapi.py| OpenAPI 语义差异与 semver 分类 |
| prcheck/engine.py | 分析编排与结果聚合 |
| prcheck/render.py | Markdown/SARIF/JSON 渲染 |
| prcheck/issues.py | Issue 数据模型与排序 |
| prcheck/cache.py  | 增量缓存 |
| action/run_action.py | Action 入口、产物落盘、集成调用 |
| action/gh_comment.py | GitHub API 封装 |
| action/webhook.py | Webhook 桥接 |
| action/action.yml | Action 输入/输出声明 |

2.4 接口设计
------------
2.4.1 命令行接口（CLI）
  prcheck -d <diff文件> [--security-only] [--data-only] [--behavior-only]
          [--min-severity info|low|medium|high] [--require-high-ok]
          [--sarif <路径>] [--json] [-o <报告路径>]
  prcheck --repo owner/repo --pr N   （经 gh CLI 拉取 PR diff）

2.4.2 GitHub Action 输入（环境变量 INPUT_*）
  INPUT_DIFF、INPUT_BASE_SPEC、INPUT_HEAD_SPEC（OpenAPI 文件路径）、
  INPUT_OUTPUT_DIR（默认 prcheck-reports）、INPUT_MIN_SEVERITY、
  INPUT_SECURITY_ONLY / INPUT_DATA_ONLY / INPUT_BEHAVIOR_ONLY、
  INPUT_REQUIRE_HIGH_OK、INPUT_POST_COMMENT、INPUT_POST_INLINE_COMMENT、
  INPUT_CHECK_MERGEABLE、INPUT_SYNC_LABELS。

2.4.3 GitHub REST API 接口（集成层调用）
  - POST /repos/{repo}/issues/{n}/comments         发布报告评论
  - PATCH /repos/{repo}/issues/comments/{id}       更新既有报告评论
  - GET  /repos/{repo}/pulls/{n}                   读取合并状态
  - POST/DELETE /repos/{repo}/issues/{n}/labels    同步阻塞标签
  - POST /repos/{repo}/pulls/{n}/comments          内联评审评论

2.4.4 输出产物
  report.md（Markdown）、report.sarif（SARIF 2.1.0）、semver.json
  （包含建议版本提升与门禁状态）。

2.5 数据结构设计
----------------
- Issue（prcheck/issues.py）
  rule_id, category(security/data/behavior), severity(info/low/medium/high),
  summary, path, line, snippet, hint, refs；按 severity 排序输出。
- 规则（prcheck/rules.py）
  每条规则含 id、category、severity、正则模式、修复提示、参考链接；
  适用文件后缀约束（如 R006-deps 仅针对依赖清单文件）。
- 分析结果（run_analysis 返回值）
  issues 列表、stat 统计、openapi_changes 列表、semver 建议。

2.6 数据库设计
--------------
本软件为无数据库的本地分析工具。持久化仅包含：
- prcheck/cache.py：增量分析缓存（本地目录 .prcheck-cache/，以内容哈希
  为键的 JSON 记录）；
- run_action.py 产物目录：report.md / report.sarif / semver.json（默认
  prcheck-reports/）。

3 详细设计
================================================================

3.1 规则引擎模块（prcheck/rules.py）
------------------------------------
输入：diff 文本。处理步骤：
1) 解析出新增的行（以 '+' 开头且非 '+++'），记录所属文件路径与行号；
2) 对每个新增行按规则列表匹配，予以文件/规则双重过滤：
   - _should_skip_path：忽略锁文件、vendored 目录等；
   - _should_skip_rule：R006-deps 仅在有依赖清单文件（requirements*.txt、
     pyproject.toml、package.json、setup.py）时适用；
3) 同一 (rule, line) 至多产生一个 Issue，避免多分支重复计数；
4) 输出按 severity 排序的 Issue 列表与分组统计。
关键规则示例：
- R001-a：新增 HTTP 路由是否缺少鉴权（high）；
- R002：硬编码密钥/口令（high）；
- R006-deps：依赖未锁定/弱锁定（medium），支持引号与非引号 pin 写法；
- R004：eval/反序列化等危险函数（medium）；
- R011-session：Session Cookie 安全属性配置（medium）；
- B003：缺少错误处理（medium）；D003：敏感数据相关（根据类别）。

3.2 OpenAPI 差异模块（prcheck/openapi.py）
------------------------------------------
输入：base 规范与 head 规范文本（YAML/JSON）。处理步骤：
1) 解析两份规范（PyYAML），支持 swagger 2.0 与 openapi 3.x；
2) 对比 paths 下每操作的路径、方法、参数列表、requestBody、响应 schema；
3) 按破坏性规则分类：
   - breaking（如删除端点、删除必填参数、收紧 schema）→ semver major；
   - non-breaking 新增（新端点、可选参数）→ semver minor（若含 new feature）；
   - 其余修正 → patch；
4) 异常输入（非法 YAML/结构）抛出 ValueError，由调用方统一处理。

3.3 渲染模块（prcheck/render.py）
---------------------------------
render_markdown：生成分级检查清单 Markdown，含文件:行号 定位、规则说明、
修复提示，以及门禁状态（High 未解决时高亮阻塞区）。
render_sarif：将 Issue 与 OpenAPI 变更映射为 SARIF 2.1.0 result/location
             （ruleId、message、physicalLocation 等）。
semver.json：版本号、建议以及 blocked/high_count 门禁字段。

3.4 GitHub 集成模块（action/gh_comment.py）
-------------------------------------------
- _api_base()/ _token()：API 基址与令牌（GH_TOKEN / GITHUB_TOKEN）解析；
- update_or_post_comment()：列出既有评论，若找到带报告标记的评论则
  PATCH，否则 POST，实现单一评论幂等更新；
- review_comments_for_issues() / post_review_comments()：按 (path,line)
  合并发现生成内联评论，重跑时按标记去重跳过，单个 API 失败不阻塞其余；
- fetch_pr_state()：GET pulls/{n}，映射 mergeable/mergeable_state/draft/
  merged/state 五个字段；
- sync_blocker_label()：门禁失败时 POST 添加 prcheck:blocked 标签，通过时
  DELETE 移除，404 视为已达目标状态。

3.5 Action 入口模块（action/run_action.py）
-------------------------------------------
主流程：
1) 读取环境输入，无 INPUT_DIFF 时用 git diff base...head 自动派生；
2) 存在 base/head OpenAPI 文件时读取并调用 run_analysis，ValueError 时以
   退出码 2 清晰失败；
3) 落盘 report.md / report.sarif / semver.json；
4) 按开关依次执行：报告评论、内联评论、合并状态读取、标签同步——每个都
   独立 try/except，失败仅写 stderr 警告；
5) 门禁判定：INPUT_REQUIRE_HIGH_OK 且存在 High 级问题时退出码 1，否则 0。

3.6 缓存模块（prcheck/cache.py）
--------------------------------
以新增文件内容哈希为键保存分析中间结果；重复分析相同内容时直接复用，
仅缓存未变化文件的结论，避免重复计算。
